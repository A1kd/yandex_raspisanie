# Расписание Путешествий (yandex_raspisanie)

Учебный проект: приложение поиска расписания транспорта на API Яндекс Расписаний.
SwiftUI, MVVM, минимальная версия iOS 17.

## Что сделано

- **Спринт 1** — сетевой слой: 8 сервисов API через OpenAPI Generator.
- **Спринт 2** — вёрстка экранов по макету Figma: заставка, главный экран, выбор
  города и станции, список рейсов, фильтры, экраны ошибок; светлая и тёмная темы.
- **Спринт 3** — карточка перевозчика, настройки с переключением темы,
  пользовательское соглашение в `WKWebView`, панель Stories на главном экране
  и полноэкранный просмотр историй.
- **Спринт 4** — экраны связаны с сетевым слоем: города и вокзалы из
  `stations_list`, рейсы с пересадками из `search`. Сетевой клиент — `actor`,
  включена строгая проверка многопоточности (`SWIFT_STRICT_CONCURRENCY = complete`).

## Структура

```
TravelSchedule/
├── App/           точка входа, заставка и таббар
├── DesignSystem/  цвета, шрифты и переиспользуемые компоненты из UI-kit макета
├── Models/        City, Station, Carrier, RouteSegment, RouteFilter, AppError
├── Mock/          данные из макета для превью и мок-провайдеры
├── Features/      экраны, каждый со своей ViewModel
├── Services/      сетевой слой: NetworkClient, сервисы API, мапперы и провайдеры
└── Resources/     Assets.xcassets и offer.html с текстом соглашения
```

## Навигация

Таббар с двумя вкладками: расписание и настройки. Внутри вкладки расписания —
`NavigationStack`: список рейсов, фильтры и карточка перевозчика открываются push-переходом.
Выбор города и станции показывается в `fullScreenCover` и перекрывает таббар,
стрелка на экране выбора города закрывает его целиком. Так же поверх таббара
открываются истории и пользовательское соглашение.

## Истории

Панель историй на главном экране — горизонтальная коллекция карточек 92×140:
непросмотренные с синей обводкой, просмотренные приглушённые. Список просмотренных
хранится в `UserDefaults`. По тапу истории разворачиваются из карточки на весь экран:
каждая держится 10 секунд, индикаторы сверху показывают прогресс, листать можно
свайпом и тапом по сторонам экрана, закрыть — крестиком, свайпом вниз или дождавшись
конца последней истории.

## Тема

Тема задаётся переключателем в настройках и хранится в `UserDefaults`.
`RootView` применяет её через `preferredColorScheme`, поэтому системная тема
на приложение не влияет.

## Данные и многопоточность

Экраны работают с API «Яндекс Расписаний». Единая точка входа в сеть —
`NetworkClient`: `actor` с асинхронным методом на каждый из восьми сервисов.
Города и вокзалы берутся из `stations_list` (ответ ~35 МБ разбирается один раз
и кэшируется внутри актора), рейсы — из `search` с пересадками; ближайшие дни
загружаются параллельно через `withThrowingTaskGroup`. Провайдеры спрятаны
за протоколами `CityProviding` и `RouteProviding`, в превью подставляются моки.

В настройках сборки включён `SWIFT_STRICT_CONCURRENCY = complete`: модели
помечены `Sendable`, ViewModel-экраны — `@MainActor`. Проверка доступности сети
(`NWPathMonitor` с callback) обёрнута в асинхронный метод через
`withCheckedContinuation` — по её результату решается, какой экран ошибки
показать: «Нет интернета» или «Ошибка сервера».

## Сборка и тесты

Проект генерируется из `project.yml`:

```
xcodegen generate
open TravelSchedule.xcodeproj
```

UI-тесты проверяют сценарии из чек-листа — открытие и закрытие историй,
переключение темы, показ соглашения поверх таббара, а smoke-тест
`NetworkSmokeUITests` проходит основной сценарий с реальным API:
выбор станций, список рейсов и карточку перевозчика:

```
xcodebuild -project TravelSchedule.xcodeproj -scheme TravelSchedule \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro' test
```
